# Pruebas automatizadas

Ubicar las pruebas en la carpeta que utiliza el proyecto real: por ejemplo, `app/test/` en Flutter o las rutas de pruebas del proyecto Android. No duplicarlas aquí.

Priorizar reglas de caducidad, cálculo de cantidades, validación, persistencia y aislamiento de inventarios. Documentar el comando real en [`docs/instalacion.md`](../docs/instalacion.md) e incluir resultados en el pull request.

Los casos funcionales de aceptación están en [`docs/pruebas/matriz.md`](../docs/pruebas/matriz.md). No se ha configurado CI ni se han ejecutado pruebas de la aplicación, porque aún falta incorporar su código.
