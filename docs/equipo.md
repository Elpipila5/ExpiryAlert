## Eventos según el plan

- Planning: inicio de cada semana; definir meta, historias y tareas.
- Daily: tres veces por semana, 10-15 minutos; avance, siguiente trabajo y bloqueos.
- Review: cierre semanal; demostrar incremento y comprobar criterios.
- Retrospectiva: cierre semanal; acuerdos de mejora para el siguiente sprint.

## Definition of Done

- [ ] Cumple los criterios de aceptación.
- [ ] Está integrado con navegación, datos y módulos requeridos.
- [ ] Funciona dentro de una versión ejecutable y demostrable.
- [ ] No tiene errores críticos en el flujo esperado.
- [ ] Valida entradas y controla errores.
- [ ] Tiene pruebas funcionales y de cálculo/permisos/conectividad cuando aplican.
- [ ] El código tiene commits identificables en el repositorio.
- [ ] Otro integrante revisó o validó el cambio.
- [ ] Tiene evidencia: captura, video, build o resultado de prueba.

## Seguimiento

Usar los estados **Pendiente → En proceso → En revisión/pruebas → Terminado**. Registrar historias terminadas/comprometidas, defectos, porcentaje demostrable, aportes técnicos y builds funcionales. No publicar un porcentaje de avance sin explicar cómo se comprobó.
